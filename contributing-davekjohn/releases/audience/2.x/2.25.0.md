# Release notes v2.25.0 🚀

**Date:** 2026-08-27  
**Type:** Minor  
**For whom:** the organisation -- what changed, and what it is worth

The contribution workflow moves into its own folder, the plugin reaches v4.20.0, and the gate now checks every link.

## What changed

**Nothing on the site moved, and nothing is asked of you.** Not one line under `src/`, `public/`,
`next.config.ts` or `netlify.toml` changed in these fifteen items -- the pages Netlify builds from this
release are byte-identical to the ones it built from v2.24.0. This release is entirely about the route
work takes to get to the site, so there is no page to check and no action to take.

### The gate now catches dead links, and it found fifteen on the first run

Every relative link and every heading anchor across the repo's 98 markdown files -- 184 links in this
run -- is checked against the actual tree before a pull request can open. It was added because a folder
move left **fifteen broken links** standing for a full day with a green gate and green CI behind them;
they were found only because a second move happened to pass over the same ground. Documentation is the
one thing here that every session reads and no compiler ever looked at. Now it is checked like code.

### The way of working lives in one folder, and the plugin that drives it is current

Everything about how work moves through this repo -- the contribution guide, the release history, the
25 hand-written release documents, the changelog, the per-branch document -- now sits in a single
folder, `contributing-davekjohn/`, instead of being scattered across the repo root. The shared plugin
went from v4.8.0 to **v4.20.0** in the same stretch, and the repo followed each of its moves: the
folder rename, the changelog's new home, and a per-branch document that went from two files plus
template copies down to one.

**One of those moves prevented a silent failure rather than fixing a visible one.** The plugin quietly
changed where generated release notes are filed, and nothing warned about it -- no script printed
anything, and the guide that warns about the neighbouring move does not mention this one. Left alone,
the very next release would have started a second, empty history tree beside the existing 41 documents
and reported success. The files were moved first; that is why this release filed correctly.

### Pushing is free again, and only work you can look at still waits for you

Two rules were simplified, both toward less waiting. Pushing to the live branch no longer needs your
word -- it had been reserved to you for a reason that had quietly expired, since merging a pull request
already writes there directly. And a pull request now waits for exactly one reason: **there is
something on the frontend to look at.** Anything touching pages, styling, mix data or images still
stops and waits for your eyes, because no gate can prove a page looks *right*. Everything else runs
through on its own.

What did not change: the protected files still need your word before they are touched at all, and
rewriting history -- force-push, hard reset, rebase -- is still refused outright. Your say now falls
once, when the work is handed out, instead of a second time at the merge button where it had become a
stamp on a decision already made.

### The documentation stopped disagreeing with the machine

Four corrections, each carrying the measurement that settled it: the test gate was described as 8
suites and 143 tests and is **16 suites and 213 tests**; a configuration file accounted for 5 of its
shared settings and now accounts for 14; a reported count of 3 turned out on a recount to be 9; and the
guide to the contribution cycle, which had briefly existed in two competing copies, is one page again.

## What it is worth

**The last release was a week of finding things; this one is about making sure the finding keeps
happening.** v2.24.0 closed 55 audit findings, and the honest question afterwards was whether that was
a one-off clean-up or a standard the repo can hold. Three of the fifteen items here answer it.

**The cheapest possible check now covers the most-read material.** Documentation drift is not a
cosmetic problem in this repo: the operating instructions are read at the start of every working
session, and a wrong instruction is acted on rather than ignored. Fifteen dead links survived a full
day behind gates that were green, which measured exactly how much confidence those gates deserved on
that material. That gap is closed for a few seconds per run.

**Being current with the shared tooling is now a maintained position instead of a growing debt.** The
plugin moved twelve minor versions in a fortnight, and each one that lands unadopted makes the next
adoption larger and riskier -- the scripts stop finding what they look for, and the failure arrives
mid-task rather than at a moment you chose. Four separate adoption steps in this release bring that
debt to zero. The one that mattered most produced no visible symptom at all: it prevented the next
release from silently filing itself in the wrong place, which is the kind of failure nobody notices
until the history is already split in two.

**Less of your attention is spent on decisions that were not decisions.** Approval used to be asked
twice for the same piece of work -- once to start it, once to merge it -- and the second ask was a
formality on a judgement already made. It now falls once, and it falls where it is genuinely needed:
on anything a person has to *look* at. Your involvement went down without the safeguard going down
with it.

**What it cost to produce: 4 minutes 14 seconds**, from starting the cut to the release being live --
against 36 minutes for v2.24.0. Three legs: the cut itself (the four-part integrity gate, all 16 test
suites, the generated notes, the commit and the tag) took **26 seconds**; writing this document and
putting it through both gates took **2 minutes 47**; pushing, publishing and attaching the notes took
**1 minute**. Two things account for the difference with the release before it, and neither is a faster
machine. This release carries 15 changes rather than 54, so there was less to describe. And the release
document no longer travels via a pull request -- it is committed straight onto the live branch under the
release exception -- which removed a review-and-merge leg that was most of v2.24.0's half hour. The
proportion held, though: writing and checking was five sixths of that run and is still two thirds of
this one.

## What was still open at this release

**One finding from the previous audit is still open, and it is the same one.** All 25 Full mixes stream
from the legacy storage bucket rather than the active one. Nothing is broken for a visitor -- the
files play -- but the repo depends on storage it has otherwise moved away from. The remaining step is
re-uploading the audio, which sits with Dave rather than with the repo. Tracked as issue #68, and it
was the only open item in this repo at the moment of this release.

**Two reports were filed upstream rather than repaired here.** Both concern the shared plugin: the
release-note relocation that arrives without any warning, and a set of relative links in a scaffolded
page that point one folder short for every repo that follows the prescribed layout. Repairing either
one locally would restart the drift for the next consumer, so they go to the source and come back in a
plugin release. Nothing here waits on them.

**Nothing about the site itself was left half-done**, because no part of this release touched the site.
The pages, the mixes and the metadata are exactly as v2.24.0 left them.
